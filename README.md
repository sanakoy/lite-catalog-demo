# lite-catalog-demo

Каталог лотов застройщика с бронированием. Небольшой пример на Python и SQLAlchemy: бизнес-правила не зависят от базы, база подключается через репозиторий, а сценарий брони собран в сервисном слое. API нет, тесты работают на SQLite.

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run pytest
uv run ruff check
uv run ruff format --check
uv run mypy
```

## Устройство

| Файл | Что внутри |
|---|---|
| `src/lite_catalog_demo/model.py` | Лот, его статусы и правила: бронь, отмена, продажа, выбор самого дешёвого. Импортов SQLAlchemy нет |
| `src/lite_catalog_demo/orm.py` | Таблица `lots` и императивный маппинг на класс `Lot` |
| `src/lite_catalog_demo/repository.py` | Порт `AbstractRepository` и адаптер `SQLAlchemyRepository` |
| `src/lite_catalog_demo/service.py` | Сценарий брони: прочитать лоты, забронировать, сделать `commit` |
| `tests/fakes.py` | `FakeRepository` и `FakeSession` для тестов без базы |

`service.py` зависит от порта, а не от адаптера. `orm.py` импортирует `model.py`, обратной зависимости нет.

## Тесты

| Файл | Что проверяет | На чём |
|---|---|---|
| `tests/test_model.py` | Правила лота и выбор самого дешёвого | Без базы |
| `tests/test_orm.py` | Загрузка, сохранение и уникальность номера | SQLite в памяти |
| `tests/test_repository.py` | Адаптер и контрактные тесты, общие для настоящего репозитория и фейка | SQLite в памяти и фейк |
| `tests/test_service.py` | `commit` при успехе и его отсутствие при ошибке; бронь видна из новой сессии | Фейк и SQLite в файле |

## Решения

- **Маппинг императивный,** чтобы `model.py` оставался обычным Python-кодом, а его тесты шли без базы. Цена: после `start_mappers()` SQLAlchemy инструментирует класс `Lot`, поэтому граница есть в исходниках, но не во время выполнения.
- **Лоты равны, если совпадает номер.** Лот это сущность с идентичностью, а не объект-значение.
- **`commit` делает сервис, а не репозиторий.** Границу транзакции определяет сценарий, а `add` только кладёт лот в сессию.
- **Порт описан через ABC, а сессия через Protocol.** Реализации порта наследуются от него явно, а `Session` это чужой класс, поэтому для `commit` достаточно структурного типа.
- **`get` бросает `LotNotFound`.** Отсутствие лота это доменная ошибка, и вызывающему коду не нужно проверять `None`.
- **Дубль номера не входит в контракт порта.** Настоящий репозиторий упирается в уникальный индекс при `flush` или `commit`, а фейк падает уже на `add`. Уникальность проверена отдельно в `tests/test_orm.py`.
- **При равной цене выбирается первый лот в порядке `list_all`.** Порядок не задан, поэтому при ничьей конкретный лот не гарантирован.
- **У клиента может быть несколько броней.** Модель это не ограничивает.

## Чего здесь нет

- **Защиты от одновременной брони.** `list_all` читает без блокировки: два клиента могут выбрать один лот, и последний `commit` молча перезапишет первую бронь. На PostgreSQL для этого нужна блокировка строки (`SELECT ... FOR UPDATE`) или колонка версии.
- **Unit of Work.** Сессия передаётся в сервис отдельным параметром.
- **Разделения порта и адаптера по файлам.** Оба лежат в `repository.py`, поэтому `service.py` транзитивно импортирует SQLAlchemy.
- **Перевода `IntegrityError` в доменную ошибку** при дубле номера.
- **Отбора лотов в запросе.** `list_all` загружает все лоты, а `book_cheapest` выбирает в памяти. Для большого каталога отбор надо перенести в SQL.
